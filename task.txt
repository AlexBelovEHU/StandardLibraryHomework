Создание резервных копий

1. Запуск

Код принимает два параметра:

путь к исходному каталогу;

путь к каталогу, в котором будут храниться резервные копии.

Пример запуска:

ts-node ./src/index.ts ./source ./backups

2. Создание резервной копии

Программа проверяет файлы, находящиеся непосредственно в исходном каталоге. Подкаталоги проверять не нужно.

Программа вычисляет хеш на основе имён файлов в исходном каталоге.

Если файлы изменились (добавились или удалились), программа создаёт резервную копию.

Если изменений нет, создание резервной копии пропускается.

Резервная копия сохраняется в формате .tar.gz. (Создается командой tar -czf "${backupFilePath}" -C "${sourceDir}")

Имя файла должно содержать дату и время создания, например:

backup-2026-10-16T12-30-45-123Z.tar.gz

3. Ведение журнала

Все результаты работы программы записываются в файл backup_log.txt.

Если резервная копия создана успешно, записать сообщение:

2026-10-16T12:30:45.123Z: SUCCESS: Backup created

Если произошла ошибка, записать сообщение:

2026-10-16T12:30:45.123Z: FAILED: tar command failed

Если изменений нет, записать сообщение:

2026-10-16T12:30:45.123Z: SKIPPED: No changes detected

4. Хранение хеша

После успешного создания резервной копии программа сохраняет текущий хеш в файле backup_log.txt.

При следующем запуске программа получает предыдущий хеш из этого файла и сравнивает его с новым.

Если хеши совпадают, резервная копия не создаётся.
